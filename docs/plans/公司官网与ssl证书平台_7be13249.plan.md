# 公司官网与 SSL 证书签发平台

## 背景与决策
- 公司已有主体但业务未定，证书是第一个产品线。主域名做品牌官网门户（备案主体），二级域名 ssl.example.com 做证书平台。
- 证书业务采用混合模式：分销（对接上游 CA）+ ACME 免费证书引流。
- 工作区 e:\code\jia-gw 当前为空，从零搭建。

## 技术栈（待确认）
- 推荐：Next.js 14（App Router）+ TypeScript + PostgreSQL + Prisma + Tailwind
- 支付：支付宝/微信（对公主体）
- 证书签发：上游 CA 开放 API / ACME 客户端（如 certbot、acme.sh）

## 实施阶段

### 阶段一：公司官网门户（主域名 example.com）
- [ ] 单页官网：Hero / 产品线入口 / 解决方案（按行业）/ 关于我们 / 底部备案信息
- [ ] SEO 基础：sitemap、robots、meta 标签、OG 标签
- [ ] 产品线入口卡片，跳转 ssl.example.com（二级域名）
- [ ] 行业方案页 + 证书知识库（SEO 内容，权重放主域名）

### 阶段二：SSL 证书签发平台（ssl.example.com）
- [ ] 用户体系：注册/登录/找回密码（对公主体需要实名）
- [ ] 商品管理：证书套餐（品牌/类型 DV/OV/EV/年限/价格）
- [ ] 下单流程：选购 → CSR 生成 → 域名验证（DNS/HTTP）→ 支付 → 签发
- [ ] 支付接入：支付宝/微信，订单状态机（待支付/已支付/签发中/已完成/失败/退款）
- [ ] 证书交付：下载（ZIP/PEM/PFX）、部署指引
- [ ] 免费证书：ACME 自动化签发（Let's Encrypt/ZeroSSL），增值功能（API/批量/监控）后续迭代

### 阶段三：管理后台
- [ ] 订单管理（审核、状态流转、退款）
- [ ] 签发管理（手动干预、对接上游 CA 订单）
- [ ] 客户管理

### 阶段四：部署与备案
- [ ] 主域名 example.com + 二级域名 ssl.example.com 部署（Nginx 反代 + 泛解析）
- [ ] 主域名 ICP 备案（公司主体信息，主域名首页即备案内容页）
- [ ] 生产环境：HTTPS、备份、监控

## 建议先决条件（需用户确认）
- 域名和服务器是否已购买？域名是否已解析？
- 公司主体是否已对公账户（支付接入必须）？
- 上游 CA 渠道是否已有（分销模式）？

## 风险与待澄清
- 分销模式依赖上游 CA 的 API 开放程度和对接成本，先选 1 家落地。
- ACME 免费证书不能用于支付等高信任场景（浏览器信任但无组织验证），需在购买页明确标注区分。
